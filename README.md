# Abstract
This application seeks to provide a digital notebook creation solution for chemistry students at Mount St. Mary's University. The interface through which users can interact is via a web page, which allows for users to log in or register a new account if they are not already logged in. These logins are tracked using session cookies to avoid frequent logins. After logging in, students would have the ability to access a web page where they can create, edit, save, and export lab notebook documents. Users also have a dedicated dashboard page where previously saved lab notebooks can be accessed. These saved notebooks as well as user login information are saved to a SQLite database.

# Problem Description
The application seeks to address some issues present in the current system of physical lab notebooks used by Chemistry students for completion of lab work. Currently, students have a dedicated lab notebook that they will use during the semester to write down all information relevant to their labs, such as a description of experiments performed and steps taken during the experiment. Students are also expected to include lab safety rules at the start of the notebook, in addition to other formatting like a table of contents and chemical index for each lab.

The first issue with physical notebooks is the potential for notebooks to be lost or damaged. Especially in a lab environment there is a possibility of accidents resulting in damage to notebooks. By having an online lab notebook the risk of lab notes being lost when personal items are damaged is negated, since all digital notebooks are saved to the application’s SQLite database. The same applies for losing lab notebooks, since digital lab notebooks can be accessed on any device via the web browser.

The other issue with physical lab notebooks is regarding handwritten notes. Many students prefer writing notes and completing assignments digitally as opposed to physical notes. This makes digital lab notebooks a good option for those students who would prefer to type assignments instead of handwriting them. Additionally, digital assignments are also much easier for professors to grade, since a number of students may not have excellent handwriting.

# Solution
In order to create a comprehensive solution that addresses current issues with lab notebooks I created a full stack application to facilitate creating and editing of lab notebooks over the web. The only hardware depended on during development is my own personal laptop, however hosting the project requires a dedicated server. All of the frontend and backend components of the application were created using the Nextjs framework, a full stack web development framework based on React. This allowed for creation of detailed and user friendly interfaces. To save edited notebooks I utilized a SQLite database to allow for a simplistic and lightweight database architecture that can be easily updated.

When accessing the application via the web, users first arrive at the home page, where they can sign in or register an account in order to start editing notebooks. Once users have logged in or if they are already logged in they can start editing by navigating to the editing page. After log in users are redirected to their dashboard page, where they can see their saved notebooks and create new notebooks. On the notebook editor page students can begin creating a new lab notebook using various standard formatting tools like headers, bolding, italicizing, and bulleted/numbered lists as well as word processing capabilities for spelling and grammar check. The notebook editing page also has access to some unique editing features like inserting preformatted sections and a drawing notepad. From the notebook editor page users can export notebooks as pdf files as well as save them for editing later.

# User Manual
## Notebooks
Notebook in this documentation refers to a single document created by a user. When using physical lab notebooks a single notebook was used for all assignments over the course of a semester, but in this implementation users are intended to create a unique notebook document for each assignment. Users can save these notebooks to access and edit at a later date as well as export them as a PDF document for submission purposes.
## Home Page
Initial landing page for users. On the homepage there is a simple message informing users they may log in to start editing notebooks. In the navigation bar there are two buttons for either logging in or registering, or to create a new notebook. If users are not already logged in, they will be redirected to the sign in page when attempting to access pages aside from the login page. If users are logged in and attempt to go to the log in page, then they will be redirected to the dashboard page.
## Notebook Editing Page
Page allowing for the editing of notebook pages. Here users can create new notebook documents with a variety of formatting options. These options include bolding, italicizing, striking, code blocks,  headers 1-5, bulleted lists, numbered lists, block quotes, section templates, and drawing pads. The section templates are preformatted text that can be inserted on the page since they are frequently used across all lab notebooks and include table of contents, lab safety rules, description of experiment, and summary of steps. Users can save their progress on this page with the save file button, as well as export the file as a pdf.
## Dashboard
The page where saved notebooks can be accessed by users. The names of all saved notebooks associated with the logged in user are displayed on the page, which will redirect to the notebook editing page with the content of that notebook loaded when users click on it. Users can also sign out of their account and will be redirected to the home page.
## Login Page
Login page allowing for users to sign in with an existing account. If users enter in a valid username and password they will be redirected to the dashboard page after authorization. From this page users can also choose to register a new account by clicking the “ Don’t Have an account? Sign Up” button. After creating a new account users are also redirected to the dashboard page.
# Designer's Manual
## Authorization of Logins
User logins are authenticated using OAuth credentials. This means when users attempt to log in the entered credentials are compared to credentials present in the database, and if the entered credentials match any present in the database the user will be authorized. This authorization status is tracked via session cookies, so users will still be logged in if they log in on a device and then enter the site again at a later time with the same device. The session cookies are also used for authentication purposes to verify if a user can navigate to a page, and to retrieve information like the username of the currently logged in user.
## Word Processing
To achieve word processing as well as standard formatting options the application leverages an open source text editor framework called TipTap. To utilize Tiptap the editor page has a formatted text box where a TipTap editor instance is instantiated. By default TipTap allows users to format text using markdown syntax. In order to also allow for formatting to be done via menu bar buttons a menu bar is created using React event handlers, this also allows for the custom notepad, template, save, and export buttons.
## Notebook Notepad
The Notepad option in the notebook editor allows for users to draw images like small diagrams and lab notation onto documents. This is achieved by creating a node to be displayed onto the page when the notepad button is clicked. This node has an edit button, which when clicked will open a model that allows for drawing on a fixed size canvas with canvas js. When edits are saved the node will then show a preview of the drawing. This node and modal setup allows for the most consistent formatting of drawings since they are of a fixed size.
## Notebook Templates
The notebook templates insert preformatted text onto the page when the associated format button is pressed. These formats include table of contents, lab safety, description of experiment, and summary of experiment steps. All of these buttons are created by making custom TipTap extensions, which allow text to be inserted via react handlers.
## PDF Export
Exporting PDFs is achieved by using Puppeteer. Puppeteer is a javascript library that allows for web automation and headless browser actions, which the application uses to extract text from the editor page. When the export button is pressed, an internal api call is made that uses puppeteer to scrape the text from the editor to format and download.
## Saving Notebooks
The application uses a sqlite database in order to save notebooks and associated data. When the save button is clicked on the notebook editing page, an internal API call is made that creates or overwrites a notebook entry for the signed in user. Each saved notebook has an id, title, content (editor content in json format), created at timestamp, updated at timestamp, and an author id. This is tracked via a relational database structure, where each user has an id and each notebook has an associated author id that matches the user that created it. A similar process is used for retrieving notebooks from the database for editing existing notebooks. When a user clicks on an existing notebook on the dashboard page they are redirected to the editing page with the notebooks title in the search parameters. Every time the editing page is loaded it checks for a notebook title in the search parameters, if there is a title then an internal api call is made to check if the database contains a notebook matching that title for the logged in user. If a notebook is found that matches the title and author id, then that notebook’s content is loaded into the editor.
